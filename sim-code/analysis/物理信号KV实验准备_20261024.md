# 物理进度感知 KV 淘汰：代码与实验输入

实验分支：`codex/physical-kv-prediction`。本次代码只准备 E2/E3 的离线决策层；尚未运行 GPU 实验，也未将策略接入 vLLM 的真实分配器。

两份原始输入 `kv_probe_robothor_k8.jsonl` 和 `robothor_k8_kvprobe_replay.jsonl` 保存在本地 `analysis/robothor_multiround_20261022/`，未发布到 GitHub。下面的回放命令需要这两份文件；其他机器须通过获授权的数据共享方式取得，或重新采集轨迹。

## 针对的 LRU 失效区间

现有研究方案中，容量 3146 块的实测轨迹有一次 `target_review` 冷回访；离线回放在 2200 块以下开始出现明显的主循环损失，在 1000 块时 LRU 多出 43,464 块缺失。该区间正是多机器人轮流回访、总工作集超过 KV 池的循环访问场景。以上是**已记录的观察与旧回放结论**，不代表新策略已有收益。

## 实现

- `scripts/serving_study/physical_kv_policy.py`：用导航剩余路径与速度、剩余转角与角速度，或操作剩余动作块与块速率，估计下次调用时间。没有物理信号时回退到会话调用间隔的指数滑动均值。`done` 事件使该机器人所有会话成为可优先淘汰的无用块。关键度调节淘汰排序，核验会话无显式权重时默认 4。
- `scripts/serving_study/kv_progress_replay.py`：在同一冻结块轨迹上比较 `lru`、`interval`、`progress`。仅使用当前时刻以前的状态事件；共享块按所有已知引用会话中最近的预计回访排序。只统计连续前缀缺失，不把块缺失直接写成延迟收益。
- `scripts/serving_study/evaluate_progress.py`：在状态更新时刻比较历史间隔和物理进度的下次调用误差、成对顺序准确率。后续调用只用于评分，不进入预测器。
- `tests/selftests/physical_kv_policy_selftest.py`：检查时间因果性、预测顺序、淘汰变化、任务结束和输入校验。

## 物理状态事件格式

每行一个 JSON 对象，`time_s` 必须是与 KV 探针 `time_ns / 1e9` **同一主机、同一单调时钟**上的秒数；事件到达时间必须是实际可观测时间。不要用轨迹结束时间反推状态，也不要把仿真墙钟当成机器人动作时间。跨主机采集时，先用同步后的时间映射生成事件，再运行回放。

```json
{"time_s":1257157540.2,"episode_id":"robot-1","role":"planner_shadow","phase":"navigation","remaining_path_m":2.4,"linear_speed_mps":0.6,"remaining_turn_deg":45,"angular_speed_dps":90,"criticality":1.0}
{"time_s":1257157541.0,"episode_id":"robot-2","role":"manipulator","phase":"manipulation","remaining_chunks":6,"chunk_rate_hz":2.0,"criticality":1.0}
{"time_s":1257157550.0,"episode_id":"robot-1","role":"planner_shadow","phase":"done"}
```

`remaining_path_m` 应为沿规划路径的剩余长度，不是目标的直线距离。一次调用后旧进度会作废，必须发新事件才能继续用物理估计。`waiting` 可用于只更新关键度，时间预测会回退到历史间隔。对于事件触发的 `target_review`，没有可用触发条件预测时会回退到历史间隔；实验必须单独报告这一类的效果。

## 检查与运行

在仓库根目录：

```bash
python3 -m unittest sim-code/tests/selftests/physical_kv_policy_selftest.py -v
python3 sim-code/scripts/serving_study/evaluate_progress.py \
  sim-code/analysis/robothor_multiround_20261022 /path/to/measured_progress.jsonl
python3 sim-code/scripts/serving_study/kv_progress_replay.py \
  sim-code/analysis/robothor_multiround_20261022 \
  --capacities 3146,2200,1400,1000 --policies lru,interval,progress \
  --progress-jsonl /path/to/measured_progress.jsonl \
  --out /path/to/replay_result.json
```

不传 `--progress-jsonl` 时，`progress` 与 `interval` 应完全一致；这只是回放兼容性检查，不能证明物理预测有效。正式实验先用独立于已有冷回访案例的轨迹，做 E2 的预测误差与排序准确率评估，再按 E3 检查真实 vLLM 的缺失、机器人等待时间和其他请求 P95。离线回放仍不建模在途 KV、预取、PCIe 竞争和时间反馈。

当前数据无物理进度事件。兼容性检查中，新 LRU 在 3146、2200、1000 块分别得到 planner 缺失 3136、3949、46600，与旧回放一致；无物理事件时 `progress` 与 `interval` 完全一致。2200 块的因果 `interval` 结果比 LRU 差，因此不能把旧表中的探索性 `phys` 数字当作这版实现的预期收益。
